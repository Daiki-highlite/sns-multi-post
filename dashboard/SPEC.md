# 2人用 投稿承認ダッシュボード

- 利用者2人が同じXアカウント、LinkedIn会社ページ、Facebookページを共同管理する。
- 原稿は承認待ちで取り込む。どちらのメンバーも編集・承認できる。
- 承認は本文・画像・投稿先・公開日時を含む特定の版に対して行う。
- 編集は未実行の予約と承認を解除する。送信中・公開済み・結果不明の原稿を変更しない。
- 投稿先が未接続の状態の承認は準備用として保存する。接続後は投稿先を確認して再承認する。
- SNSごと・Xの枝番ごとに実行状態を保存する。既に成功した処理を再送しない。
- 応答不明や送信中断は要確認とし、自動再送しない。SNS上で確認した公開結果を記録できる。
- 未来の予約は定期実行で処理する。承認直後の実行と、定期実行の設定は別で管理する。
- カレンダーは元ファイル・タブ・投稿IDで照合し、行の並び替えで新規企画にしない。
- 画像制作状況と公開状況を混同しない。制作指示と完成画像を分ける。
- 閲覧・操作・画像取得を認証し、アクセスできるメールアドレスを2人に制限する。

実装と運用手順はREADME、外部APIの仕様は各サービスの現行公式資料を参照する。

## 一括登録

未承認の原稿をまとめて選び、公開日の再配置・SNS・画像の共通条件をプレビューして保存する。元の予定を保持することを初期値とする。開始日から再配置する場合も本文の開催日や締切は変更しない。確認が必要な原稿を除外して承認する場合は、その選択を明示する。共同編集による版の変化は上書きせず保留する。

## 承認専用ダッシュボード

- 承認待ち・承認済み・公開済み・要確認の件数を小さな横並びで表示する。
- 公開予定が近い未承認の原稿を1枚ずつカードに表示する。SNS別本文・Xの続き・添付画像・投稿先・公開日時を読み取り専用で確認する。
- 右スワイプ・✓・カードにフォーカスして右矢印で、追加ダイアログなしに表示中の原稿を承認する。指定済み日時を保ち、即時公開には切り替えない。
- 左スワイプ・×・左矢印は本文・予定日時の修正画面を開く。「保存してあとで」は修正文と任意の保留メモを共有保存して次へ進む。「修正して承認」は保存した新しい版を承認する。保留分は別一覧で確認でき、再読み込み・共同利用者にも引き継ぐ。
- 短いタップ・縦方向の移動・キャンセルされたジェスチャーでは承認しない。保存処理中は次の操作を受け付けず、失敗した原稿はカードに戻す。
- 直前の保留または承認を1回取り消せる。承認取り消しは、同じ版で公開処理・公開済み・結果不明の送信がないときにサーバーで行う。
- カード表示時の版と投稿先を固定する。他の利用者が原稿や接続先を更新した場合は最新内容を確認するまで承認できない。日時・画像・文字数の条件を満たさない原稿も承認できない。
- 本文・予定日時は「あとで」からも修正できる。削除・画像登録・取り込み・一括設定は投稿管理側に置く。SNS接続などは折りたたんだ管理メニューに置く。

## 指定したSNS投稿先

- 投稿先URLは実行環境で保持し、公開リポジトリに実アカウントの設定を保存しない。
- Xはユーザー名、LinkedIn会社ページとFacebookページはページIDをURLから取り出す。LinkedIn管理画面URLは公開ページURLへ正規化して表示する。
- 指定済みと接続済みを区別して表示する。ページIDは接続画面に自動入力する。
- 接続時に本人のSNS認証情報から取得したID・Xユーザー名と指定先を照合する。指定先の変更後に残った接続も送信前に照合し、不一致は送信を停止する。

## SNS別のスマートフォンプレビュー

- 承認カードでSNS別のSP投稿表示を切り替える。最大幅390pxとし、狭い画面では利用可能な幅に合わせる。
- アプリ本体はHighliteブランドを保ち、投稿内はSNSごとの書体・プロフィール欄・余白・反応アイコン・画像配置に寄せる。
- 投稿本文と画像の構成は送信対象から生成し、Xの続きに親投稿の画像を重複させない。
- LinkedIn・Facebookの長文は折りたたみと展開に対応する。添付画像は1〜4枚の表示に対応する。
- 実ヘッダーのキャプチャと実プロフィール画像・名前を会員専用R2と設定に保存して使用し、SNSの背景・文字色を合わせる。参照日とWeb表示の基準を示し、登録前は参照未登録と表示する。取得していない反応数・フォロワー数・リンクカードを作らない。
- SNSタブの操作・縦スクロール・本文の展開で承認しない。スワイプと✓の承認、保留、取り消しは既存の仕様を保つ。
