# Highlite 投稿ダッシュボード

X、LinkedIn会社ページ、Facebookページの原稿を2人で確認・承認し、公開するための非公開Webアプリです。既存の投稿原稿作成スキルとは独立したアプリとして動作します。

## 使い方

1. 招待されたメールアドレスでダッシュボードにログインします。
2. ダッシュボードで承認待ち・予約済み・公開済み・要確認の件数を確認します。
3. 1枚ずつ表示されるカードでSNS別本文・画像・公開日時を確認し、右スワイプまたは✓で承認します。確認ダイアログを挟まず次のカードに進みます。左スワイプまたは×は「あとで確認」に残します。
4. 「ひとつ戻る」で直前の保留・承認を取り消せます。承認の取り消しは公開処理が始まる前に限ります。
5. 原稿の編集、作成、取り込み、一括設定は「投稿管理」で行います。ダッシュボードでは本文や設定を変更できません。
6. 投稿カレンダー、画像、履歴、SNS接続は「管理メニュー」から開きます。公開結果と投稿URLは投稿の詳細・アクティビティで確認します。

承認した版の本文・画像・投稿先だけを送信します。編集は承認と未実行の予約を解除します。結果不明の送信を自動再送しません。SNSの接続先アカウントが変わった場合も再承認が必要です。

## 機能

- スワイプ・✓で1件ずつ承認するダッシュボード、小さな件数表示、保留と直前操作の取り消し
- 投稿管理、月間カレンダー、検索、企画・状態による絞り込み
- SNS別の本文編集・プレビュー、画像の共有・添付、Xの枝番の取り込み
- 個別・複数投稿の承認、予約取り消し、媒体単位の送信結果と再試行
- 共有D1データベース、非公開R2画像保管、認証情報のAES-GCM暗号化
- Google Sheetsの読取専用同期、CSV/JSON取り込み、差分確認
- 楽観ロックによる同時編集検出、原子的な送信ジョブ取得、処理中断時の重複送信抑止

## 一括登録の使い方

「投稿管理」の「まとめて登録」から、対象選択・共通条件・確認の3段階で進みます。企画や期間で絞り込み、開始日からの日付の再配置、SNSの選択、画像なし・個別画像・共通画像を一度に指定できます。初期値はカレンダーの公開予定と画像設定を保持します。

最後にSNSごとの原稿・公開予定・投稿数を確認し、下書き保存または一括承認を選びます。文字数や画像などの条件を満たさない原稿は表示され、明示的に選択した場合だけ、準備できた原稿を承認して残りを下書きに残せます。操作中に他の人が更新・承認した原稿は上書きせず保留します。

「設定・SNS連携」の「まとめて接続」では、3つのSNSの接続情報を1画面で入力できます。入力したSNSだけを確認・保存し、失敗した接続は個別に修正して再登録できます。

画面の色・書体・ロゴ・ボタン・余白は [Highlite Brand Guidelines](https://highlite.co.jp/brand-guidelines/) を参照し、`app/brand.css` にまとめています。原本のロゴ素材を使用し、Paper・Ink・Muted・Deep blueを役割に合わせて適用しています。

## 初回セットアップ

Node.js 24を推奨します。

```sh
cd dashboard
npm ci
cp .env.example .dev.vars
```

`.dev.vars` に暗号鍵（32バイトの標準Base64）と32文字以上の予約実行用シークレットを設定します。生成例：

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

次の順序で起動します。

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_chunky_starfox.sql
npm run dev
```

初回はローカルの `/signin-with-chatgpt?return_to=/` でテスト用ユーザーとしてサインインします。ローカルのデータと本番の共有データは別です。公開する場合はSitesの配信経路で認証します。直接のWorker URLを無保護で公開して、認証ヘッダーを信頼する構成にはしないでください。

## 本番の共有と接続

本番はSitesの招待制アクセスと `ALLOWED_USER_EMAILS` の両方で制限します。2人分のメールアドレスだけを設定してください。GitHubを共有するだけでは、本番アプリの閲覧権限や共有データは渡りません。

Sitesの環境変数に `CREDENTIAL_ENCRYPTION_KEY` と `SCHEDULER_SECRET` をシークレットとして登録します。投稿先は `DESTINATION_X_URL`、`DESTINATION_LINKEDIN_URL`、`DESTINATION_FACEBOOK_URL` に設定します。設定画面と原稿カードに指定先を表示し、ページIDは自動入力します。接続時にXのユーザー名・会社/ページIDを照合し、送信時も保存した接続先が指定先と一致していることを確認します。URLの指定だけではSNSへの接続完了になりません。

SNSの接続情報はダッシュボードの「設定・SNS連携」で登録します。登録時に対象アカウントを読み取って確認し、暗号化してD1に保管します。トークンを画面へ再表示するAPIはありません。

| SNS | 登録するもの |
| --- | --- |
| X | ユーザーコンテキストの投稿・読み取り権限を持つアクセストークン。画像投稿には媒体アップロード権限も必要 |
| LinkedIn | 利用審査済みの会社ページ投稿・組織参照に必要な権限を持つトークンと組織ID |
| Facebook | 投稿対象ページ用の、ページ投稿・必要な読み取り権限を持つトークンとページID |

接続情報の発行・審査・継続更新は各SNSの開発者管理画面で行います。期限切れ時は再接続します。Xの自己返信は利用条件とアカウントでの動作を確認してから `X_THREADS_ENABLED=true` を設定してください。

## 投稿カレンダーの取り込み

Google Sheetsからタブ単位でダウンロードしたCSVを読み込めます。元のスプレッドシートURLと対応するタブを指定してください。CSVの改行・カンマ・引用符を保持します。

継続読み込みは、Google Sheets APIを有効にしたサービスアカウントに対象ファイルの閲覧権限を付与し、`GOOGLE_SERVICE_ACCOUNT_EMAIL` と `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` をSitesのシークレットに設定すると利用できます。権限は `spreadsheets.readonly` です。ファイルを一般公開する必要はありません。投稿URLのシートへの書き戻しは実装していません。

対応する列は、日付（JST）、主テーマ、投稿テーマ、枝番、X 本文、LinkedIn 本文、Facebook 本文、投稿時刻（案）、投稿ID、投稿方法・つなぎ方、補足・運用メモ、URL・出典、画像案・掲載文字、画像制作プロンプト、制作状況、X 投稿URL、LinkedIn 投稿URL、Facebook 投稿URLです。

JSON取り込みは次の形式です。ヘッダーはCSVと共通です。

```json
{"spreadsheetId":"your-spreadsheet-id","tabs":[{"name":"企画名","sheetId":123,"rows":[["日付（JST）","主テーマ","投稿テーマ","枝番","X 本文","LinkedIn 本文","Facebook 本文","投稿時刻（案）","投稿ID"],["2027/01/01","ナレッジ","投稿テーマ","1/1","Xの本文","LinkedInの本文","Facebookの本文","12:00","PLAN-001"]]}]}
```

取り込みだけでは公開しません。変更された原稿は選択して適用します。予約済みの原稿は再取り込みで上書きしません。削除された行で予約を自動的に取り消すこともありません。

## 予約実行

承認直後はWorkerのバックグラウンド処理が公開時刻を過ぎたジョブを確認します。将来の予約は別途定期実行が必要です。

リポジトリの `publish-approved.yml` は5分間隔の実行用です。次のGitHub Actionsシークレットを設定し、リポジトリ変数 `ENABLE_AUTO_PUBLISH=true` を設定すると有効になります。

- `DASHBOARD_URL`：Sitesの本番URL
- `SITES_SERVICE_TOKEN`：そのSiteのサービスアクセス用トークン
- `DASHBOARD_SCHEDULER_SECRET`：本番の `SCHEDULER_SECRET` と同じ値

定期実行は `POST /api/jobs/run` だけを呼びます。投稿の承認や原稿の変更は行いません。GitHubの定期実行は遅延する場合があり、公開時刻の厳密な保証には向きません。予定から10分以上過ぎた未送信分は送信せず、確認対象にします。分単位の定時性が必要な場合は、同じエンドポイントを毎分呼ぶ専用スケジューラーを設定してください。

## 検証

```sh
npm run typecheck
npm test
# 確認用データベースでdevサーバーを起動した状態だけで実行
node tests/http-smoke.mjs
npm run build
```

単体テストはCSVと枝番の読み取り、日時、承認前提、送信版・投稿先の固定を検証します。HTTPテストはローカルに検証用下書きを作り、同時承認、古い編集の拒否、編集時の承認解除、権限を検証して削除します。実際のSNSへのテスト投稿は行いません。

## GitHubに保存しないもの

投稿カレンダーの原稿・CSV/JSON、画像、データベースの実データ、メンバーのメールアドレス、アクセストークン、環境変数ファイル、公開用アーカイブをコミットしません。`.local/`、`.dev.vars`、`.wrangler/`、`outputs/` は除外済みです。
