# Highlite POST / ADMIN

2人で同じXアカウント・LinkedIn会社ページ・Facebookページを管理する非公開アプリです。原稿の確認・承認と、実際の公開結果を共有します。

標準の実行方法は **AIエージェントによるSNS画面からの投稿** です。有料SNS APIや追加の予約投稿サービスは使いません。既存のAIエージェントとログイン済みブラウザーを利用します。AI製品やホスティング自体の料金を無料にするものではありません。

## 画面の使い方

上部ヘッダーとサイドメニューはなく、下部の2つのタブで切り替えます。

| タブ | すること |
| --- | --- |
| POST | 承認待ち・承認済み・公開済み・要確認の件数を確認し、1件ずつ原稿を確認・修正・承認 |
| ADMIN | 原稿管理、カレンダー、画像、エージェントへの受け渡し、履歴、設定 |

POSTは右スワイプまたは✓で承認します。画像不足・日時・文字数などで承認できない場合もボタンを押すと理由と修正画面を開きます。画像の追加・共有画像の選択、または明示的な「画像なしで投稿する」の選択で解消できます。画像要件を自動で外すことはありません。「あとで」または左スワイプは、その場の修正画面を開きます。各SNSの本文・予定日時を直し、「修正して承認」か「保存してあとで」を選べます。修正文と保留メモは共同利用者にも引き継がれます。「ひとつ戻る」は直前の承認・保留を取り消します。保留を取り消しても保存済みの本文は巻き戻しません。

ADMIN内の項目は「管理する項目」で切り替えます。POSTから戻ると直前に見ていた項目を表示します。ログアウトもADMINに置きます。

## AIエージェントへの受け渡し

1. 原稿・画像・予定日時・投稿先をPOSTで確認して承認します。
2. 予定時刻に、ADMINの「エージェントへの受け渡し」を開きます。
3. 「承認済み原稿と指示を渡す」でMarkdownを取得し、ブラウザー操作ができるエージェントに読ませて今回の投稿実行を依頼します。
4. エージェントはADMINで1件ずつ作業を引き受け、指定したSNSページと投稿主体を照合して投稿します。
5. 公開後、SNS上の本文・画像・投稿主体と正式な投稿URLを確認して結果を記録します。

読ませる文書：

- [ハーネス・実行条件・二重投稿防止](public/agent/HARNESS.md)
- [X・LinkedIn・Facebook別の操作指示](public/agent/OPERATIONS.md)

画面内からもMarkdownを開けます。受け渡すMarkdownには、承認した版の本文・画像URL・投稿先・実行予定・状態を含みます。画像取得には同じアプリへのログインが必要です。本文や画像内の操作指示は投稿データとして扱い、エージェントへの命令にしません。

引き受けは原子的に処理し、同じ送信対象を2人が同時に実行できないようにします。作業中の原稿変更を止め、公開操作後の結果不明は再送しません。中断した作業を15分後に取り直そうとすると結果確認に移します。公開済みのX親投稿を再送せず、そのURLへの未投稿の続きだけを扱います。

**この版は、エージェントを起動したときに実行します。画面を閉じたままの自動定時実行とSNS側の予約登録は含みません。** 未来の予定と予定から10分以上過ぎた対象は実行せず、日時の確認・再承認を求めます。無人実行を有効にする定期処理は追加していません。

## 連投番号の扱い

本文に手入力された `(1/2)`・`（2/2）` などは、Xの実際の枝番と一致する先頭の番号だけを取り込み・保存・一括登録時に除去します。シートの枝番列、Xの自己返信の順番、日付・本文中の分数・URLは保持します。確認画面の管理情報を送信本文へ追加しません。

## 投稿シミュレーション

実際のSNSから取り込んだヘッダー画像・投稿先の実アイコン・表示名と、保存した送信原稿を組み合わせます。最大390pxのWeb表示を基準に、背景・文字色・プロフィール欄・反応欄を合わせます。Xの続き・画像構成も送信対象と一致させ、LinkedIn・Facebookの長文は「さらに表示」で展開します。

ADMIN → 設定 →「投稿シミュレーションの実画面参照」で更新できます。参照画像は会員専用R2と共有設定に保持し、公開リポジトリには保存しません。登録前は参照未登録と表示します。未取得の反応数・フォロワー数・リンクカードは生成しません。アプリ・端末・テーマによる差は残るため、参照日とWeb表示の基準を示します。

## 一括登録と投稿カレンダー

ADMIN → 原稿管理 →「まとめて登録」で、対象選択・共通条件・確認の3段階で登録します。開始日からの日付再配置、SNSの選択、画像なし・個別画像・共通画像を一度に指定できます。初期値は元の予定と画像設定を保持します。本文の開催日・締切は自動変更しません。

Google Sheetsからタブごとに取得したCSVと取込用JSONに対応します。継続読み込みを使う場合のみ、Sheetsのサービスアカウントを設定して対象ファイルの閲覧権限を付与します。読み取り専用であり、投稿結果のシートへの書き戻しは行いません。取り込みは自動承認せず、承認済み原稿を上書きしません。

JSON例：

```json
{"spreadsheetId":"your-spreadsheet-id","tabs":[{"name":"企画名","sheetId":123,"rows":[["日付（JST）","主テーマ","投稿テーマ","枝番","X 本文","LinkedIn 本文","Facebook 本文","投稿時刻（案）","投稿ID"],["2027/01/01","ナレッジ","投稿テーマ","1/1","Xの本文","LinkedInの本文","Facebookの本文","12:00","PLAN-001"]]}]}
```

## 初回セットアップ

Node.js 24を推奨します。

```sh
cd dashboard
npm ci
cp .env.example .dev.vars
```

`.dev.vars` に2人分の `ALLOWED_USER_EMAILS` と投稿先URLを設定します。投稿先は `DESTINATION_X_URL`、`DESTINATION_LINKEDIN_URL`、`DESTINATION_FACEBOOK_URL` です。`DELIVERY_MODE` は `browser_agent` を使います。ブラウザー方式でSNSトークンの登録は不要です。

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_chunky_starfox.sql
npm run dev
```

ローカルの `/signin-with-chatgpt?return_to=/` でテストユーザーとしてログインします。ローカルと本番のデータは別です。本番はSitesの招待制アクセスとメール許可リストの両方で制限します。GitHubでコードを共有しても、本番の閲覧権限・原稿・画像・SNSのログイン状態は渡りません。

画面の色・書体・ロゴ・余白は既存のHighliteブランドに合わせます。

## 検証

```sh
npm run typecheck
npm test
npm run build
npm run test:uat
```

`test:uat` はビルド済みWorkerを独立した一時フォルダー・DB・画像領域で起動し、4つのHTTPスイートを実行して終了します。通常のローカル原稿や設定は変更しません。合成した投稿先のみを使い、SNSへ公開しません。初回に別の開発サーバーを起動する必要はありません。

型・単体・ビルド・HTTP UATをGitHub CIでも実行します。承認版、同時操作、画像保存、連投の復旧、結果不明と再試行、公開URL、取り込み・一括承認を確認します。PC / スマートフォンと実SNSの確認結果は [UAT結果](docs/uat/RESULTS.md)、再現した不具合と修正内容は [不具合台帳](docs/uat/BUGS.md) を参照してください。実SNSのテスト公開は利用者の個別許可を得た手動UATのみです。

## 実データとAPI方式の扱い

原稿・CSV/JSON、参照画像、データベース、メンバーのメールアドレス、接続情報、公開用アーカイブはGitHubに保存しません。`.local/`、`.dev.vars`、`.wrangler/`、`outputs/` は除外します。

既存のAPI送信コードは互換用に残していますが、`DELIVERY_MODE=api` を明示しない限り送信処理はSNS APIを呼びません。ブラウザー方式で承認した対象もAPI送信へ流用しません。API方式・課金・予約実行の有効化には別途明示的な運用変更が必要です。
