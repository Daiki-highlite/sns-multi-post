# SNS側の予約投稿

更新日：2026-11-09。対象は標準のブラウザーエージェント方式。

## 利用の流れ

1. POSTのカードにある「投稿日時（日本時間）」を変更して✓で承認する。未来なら予約投稿、現在・過去なら今すぐ投稿として表示する。「今すぐ」で現在時刻へ切り替えられる。
2. 日時・投稿方法・承認版を同時に保存し、本文・画像・投稿先とともに送信対象へ固定する。承認後の表示は「予約登録待ち」。
3. ADMINからMarkdownを渡し、AIエージェントに今回の登録を依頼する。承認ボタン自体はSNSを操作しない。未来の投稿も今から引き受け、SNS側の予約機能へ登録する。
4. エージェントはSNSの予約一覧で本文・画像・投稿主体・日時を照合し、管理画面URL・日時・確認メモを記録する。この確認後に「予約済み」になる。
5. SNSが指定時刻に公開する。アプリ・PCの常時起動や時刻ごとのエージェント起動は不要。公開済みは実際の投稿と正式URLを確認してから記録する。

## 状態と変更

| 状態 | 意味・操作 |
| --- | --- |
| 予約登録待ち | アプリでの承認済み。SNSへの登録はこれから。引き受け前なら承認解除・日時修正ができる |
| 作業中 | 担当者が登録中。編集・二重引き受けを止める |
| 一部予約済み | 一部SNSへの登録完了。他SNSは引き続き登録する |
| 予約済み | 全送信対象の予約登録が確認済み。再登録しない |
| 結果を確認 | 操作後のタイムアウトや作業中断。予約の有無を確認し、確認なしで再実行しない |
| 公開済み | 全件の実際の公開を確認し、正式URLを記録済み |
| 予約取消済み | SNS側で全件の取消完了を確認・記録済み。承認解除して修正できる |

予約済みの原稿をアプリだけで変更・削除して、外部の古い予約を残すことはできない。SNS側の予約を全件取り消し、ADMINで取消結果を記録してから承認解除・修正・再承認する。取消記録ボタンはSNS側の予約を操作しない。

## SNSごとの条件

- Xの予約連投は親から全件を一括で引き受け、全件の日時・順序・返信関係を確認して記録する。子の個別予約や独立投稿への置換を行わない。公開確認では全件の異なる正式URLが必要。
- LinkedIn会社ページは1時間以上先・3か月以内、画像は最大1枚として承認時・登録直前に検証する。実行時の条件は対象SNSだけに適用し、LinkedInの条件でXの登録を止めない。[LinkedIn公式ヘルプ](https://www.linkedin.com/help/linkedin/answer/a1419179/schedule-a-post-for-a-linkedin-page?lang=en)
- Facebookの予約可能期間・投稿形式は現在のページやMeta Business Suiteの画面で確認する。未確認の上限・下限をアプリで断定しない。
- SNSで指定日時を選べない場合は止めて理由を記録する。即時公開へ切り替えたり、日時をずらしたりしない。

## 実装と検証範囲

受け渡しJSONはschemaVersion 2。`operation` は `schedule`（予約登録）、`publish`（即時公開）、`verify`（予約後の公開確認）。登録済みの未来の予約と完了済みの作業は通常の受け渡しから除外する。

承認・引き受け・連投の結果記録は同時操作を考慮して更新する。予約日時が過ぎた対象は即時公開へ自動変更しない。未操作が確実な失敗の再試行でも承認済み日時を保ち、15分を過ぎた作業は結果不明へ移す。

アプリ内の予約証拠は、エージェント・担当者がSNS画面で照合した管理URL・日時・メモの記録であり、SNS APIからの確認ではない。SNS側で手動変更した内容の自動同期は行わない。

検証結果は [予約投稿のUAT](uat/NATIVE_SCHEDULING.md) を参照。Xで2件の連投に日時を設定する画面は確認したが、今回新たな実SNSの予約登録・指定時刻の自動公開は実施していない。
