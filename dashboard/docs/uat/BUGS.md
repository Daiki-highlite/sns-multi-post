## 環境依存のリリース条件

- 共有Sitesへの更新は、公式のソース反映経路が実行環境で拒否されたため未完了。ユーザーの許可は取得済み。これをアプリのテスト成功と混同しない。
- 実際の2人目のログインは、本人の認証セッションでのみ確認する。ローカルの権限検証と区別する。

## 受け渡しで確認した改善

- BUG-007（P1、コードと出力で確認）: 作業単位の受け渡しが古い画面データを使い、相対リンク先のSNS操作手順もファイルに含まれていなかった。最新データからIDで再選択し、ハーネス・SNS操作手順・JSONを1つのMDへ収録した。単体テストと実際のダウンロード内容で確認済み。公開済みの作業は除外する。
- ログイン期限・非JSON応答・通信失敗を読める案内に変更。実行結果が曖昧な場合は状態を再取得し、同じ操作の繰り返しを促さない。

## 予約投稿対応時の回帰確認

| ID | 重要度 | 症状・不足 | 修正と確認 |
| --- | --- | --- | --- |
| NS-001 | P1 | 未来の対象は予定時刻まで引き受けできず、SNS側の予約機能へ登録できない | `schedule` 操作を追加し、未来でも引き受け可能に。全SNSの合成HTTP確認が合格 |
| NS-002 | P1 | 承認日時の変更と承認を別処理にすると古い日時で承認する恐れがある | 日時・版・承認を一括更新し、競合は片方のみ成功。HTTPと画面で確認 |
| NS-003 | P1 | 予約を公開と同じ成功にすると、未公開や連投の一部だけを成功と誤認する | 予約済みを分離。連投を一括記録し、時刻前の公開記録と重複登録を拒否。HTTP合格 |
| NS-004 | P1 | 再試行で承認済みの予約日時が現在に変わる | ネイティブ予約の再試行は日時を保持。結果不明は再試行を拒否。HTTP合格 |
| NS-005 | P2 | スマートフォン幅で5番目の件数表示が欠ける | 5列と縦配置を明示。320px・390px幅で全件数と横はみ出しなしを確認 |

| NS-006 | P1 | 同じコードのGitHub CIの一方で画像アップロードが503（保管先の欠落）、もう一方は成功。以前のCIでも再現 | Workerが受け取ったDB・画像保管先をリクエストごとに保持して遅延ロードされる処理へ渡す。並行リクエスト分離の単体テストと、起動直後の画像保存・取得のHTTP検証を追加。SDK内部の欠落原因までは未特定 |

新しい実SNSの予約登録・自動公開は未検証。制限や実画面で全件を確認できない場合は中止する手順を定め、成功とは報告しない。
