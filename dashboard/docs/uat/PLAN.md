# ローンチ前UAT計画

実施日: 2026-11-09（日本時間）
対象: POST / ADMIN、ブラウザー投稿エージェント、GitHubで共有する配布コード。

## 合格条件

- 原稿取り込みから承認、引き受け、SNS公開、結果記録まで完了できる。
- 二重投稿、別アカウントへの投稿、未承認原稿の送信、保存後の本文の取り違えを防ぐ。
- 失敗・遅延・再読み込み・共同操作後も、安全な復旧経路がある。
- P0 / P1の再現済み不具合が未修正のまま残っていない。
- 実SNS公開を伴う確認、共有環境への配信、2人目の実ログインは、それぞれ実施証拠がある場合だけ合格にする。未実施を合格扱いしない。

## 実行環境とデータ

- 通常のプレビューと検証用データベース・画像領域を分離する。
- 自動テストはlocalhostだけで実行し、合成した投稿先・原稿・画像を使用する。有料APIは呼び出さない。
- 配布時と同じビルド済みWorkerを使い、メンバーA / B / 許可外ユーザーのリクエストを検証する。認証プロキシ由来のヘッダーはローカルの検証環境だけでエミュレートする。
- ブラウザー操作UATはPCと390px幅で実施する。実SNSの公開はユーザーが承認したテスト原稿だけを扱う。
- 実アカウントの設定、ブラウザー認証、原稿、公開証跡は非公開ローカル領域に保持し、GitHubには汎用の計画・結果・再発防止テストだけを保存する。

## テストシナリオ

| ID | 対象 | 確認内容 |
| --- | --- | --- |
| UAT-01 | 新規導入 | クローン相当の環境で設定・DB初期化・起動できる。設定不足の案内が出る |
| UAT-02 | 権限 | A / Bが共有データを扱え、未ログイン・許可外ユーザーは拒否される |
| UAT-03 | 取り込み | CSV / JSON、再取り込み、重複、枝番、不正形式を確認する |
| UAT-04 | 原稿編集 | 各SNSの文字数、空欄、連投番号、日付・URLの保持を確認する |
| UAT-05 | 日時 | 未来・現在・過去・不正な日時を確認し、遅延した作業の復旧を確認する |
| UAT-06 | 画像 | 正常画像の保存・取得・添付、不正形式、画像必須、画像なしの明示選択 |
| UAT-07 | 承認 | スワイプ / ボタン、阻害理由、修正後の版の承認、解除、二重クリック |
| UAT-08 | 保留 | 本文・メモの保存、再読み込み、他セッションへの共有、保留の解除 |
| UAT-09 | 共同編集 | 古い版の編集・承認、同時承認・同時引き受けの競合 |
| UAT-10 | 連投 | 親投稿と続き、3件以上、画像は親だけ、途中停止からの再開 |
| UAT-11 | 公開証拠 | 各SNSの正式URL、エンコード、別SNS / 別アカウント / プロフィールURL拒否 |
| UAT-12 | 結果不明 | 再投稿を止め、確認済みの公開結果を正しく記録できる |
| UAT-13 | 再試行 | 未投稿が確実な失敗と、結果不明を区別し、安全に復旧する |
| UAT-14 | 引き継ぎ | MarkdownとJSONが完全・最新で、本文・画像・版・投稿先・返信先が一致する |
| UAT-15 | エラー | 保存 / 引き受け / 結果記録の失敗、認証切れ、再読み込みで入力と状態を取り違えない |
| UAT-16 | 画面 | PC / スマホ、POST / ADMIN、キーボード、画面端・フッター・モーダルの重なり |
| UAT-17 | 課金防止 | 標準方式ではSNS API送信・API認証設定・自動定時送信を実行しない |
| UAT-18 | GitHub | 新しい環境のCIで型・単体・実HTTPの回帰テスト・ビルドが通る |
| UAT-19 | 実SNS X | 承認したテスト原稿を親投稿と自己返信で公開し、正式URLと本文・投稿主体を確認する |
| UAT-20 | 実SNS LinkedIn | 指定会社ページからテスト公開し、正式URLと本文・投稿主体を確認する |
| UAT-21 | 実SNS Facebook | 指定ページからテスト公開し、正式URLと本文・投稿主体を確認する |
| UAT-22 | 共有環境 | 共有URLが最新ビルドであり、招待した2人が利用できる |

## 記録と修正手順

1. 修正前の再現結果を `BUGS.md` に記録し、ユーザーへ報告する。
2. 再現テストを残して実装を修正する。
3. 当該テスト、関連フロー、実際のブラウザー操作で再確認する。
4. `RESULTS.md` に合格・不合格・未実施・環境依存の区別とローンチ判定を残す。
