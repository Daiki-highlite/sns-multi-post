# SNS別の操作指示

先に [HARNESS.md](HARNESS.md) を読み、ユーザーから今回の実行依頼があること、ADMINで作業を引き受けたことを確認する。画面の名称や配置は変わるため、必ず現在の画面を読み取り、見えている操作対象から進む。推測したボタンや座標で公開しない。

## X

- 受け渡しデータの `destination.url` を開く。投稿主体のユーザー名と `destination.username` を照合する。
- 親投稿は通常の投稿欄を開く。続きは `replyTo` に記録された公開済みの自分の投稿を開き、返信欄から入力する。
- 本文は `text` のまま使う。`media` が指定された対象だけ画像を添付する。Xの続きへ親投稿の画像を重複添付しない。
- 公開後に本文と投稿主体を確認し、観測した `https://x.com/<指定ユーザー名>/status/<投稿ID>` を記録する。

## LinkedIn会社ページ

- `destination.url` の会社ページを開き、会社の投稿作成画面へ進む。個人としての投稿になっていないか、投稿主体の表示を確認する。
- 本文・画像・公開範囲・リンクの扱いを確認する。SNSが生成したリンクカードと添付画像が競合し、承認内容と違って見える場合は止める。
- 公開後、会社ページの投稿として表示されることを確認する。
- 実際の投稿メニューから正式なURLを取得する。`/feed/update/urn:li:activity:…`、`/feed/update/urn:li:share:…` または `/posts/…-activity-…` 形式を記録する。会社ページのトップURLは公開証拠にならない。

## Facebookページ

- `destination.url` のFacebookページを開く。個人アカウントで見ている場合、必要なページの投稿主体に切り替えられるか画面で確認する。
- 個人プロフィール、別ページ、グループへ投稿しない。ページの名前と指定URLを確認する。
- 投稿作成画面で本文・画像を入力し、ページとして公開されることを確認する。
- 公開後、投稿の日時やメニューから実際の投稿詳細を開く。指定ページIDを含む `/permalink.php?story_fbid=…&id=…` または `/<指定ページID>/posts/<投稿ID>` の正式なURLを記録する。
- `/share/p/…` の共有短縮URLやページのトップURLでは記録しない。正式URLを観測できない場合は推測せず結果確認に残す。

## 予約機能と追加費用

この版では予定時刻にエージェントを起動して公開する。SNS側の予約画面への登録は扱わず、未来の投稿を「公開済み」として記録しない。有料APIの契約・追加課金・外部の予約投稿サービスは利用しない。無人の定時起動やSNSネイティブ予約への対応は別途検証する。
