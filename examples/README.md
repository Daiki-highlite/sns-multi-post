# Examples — 投稿の蓄積

Claudeが次回以降の投稿生成で参考にする、過去事例のアーカイブ。
**蓄積するほどスキルの精度が上がる**。

---

## 構造

```
examples/
├── good/   ← 良かった投稿（採用 + 反応が良かったもの）
└── bad/    ← 失敗した投稿（採用しなかった案 / 反応が薄かったもの）
```

---

## 各エントリのフォーマット

ファイル名: `{YYYY-MM-DD}-{テーマslug}.md`
例: `2026-04-28-kpi-redesign.md`

### good/ エントリの中身

```markdown
# {テーマ}

> 投稿日: 2026-04-28
> 担当: Daiki
> ピラー: 2 (数字×検証)

## 入力メモ
（input-memo の内容）

## 採用した案
- YouTrust: B
- LinkedIn: ★C
- Facebook: A
- X: ★C（スレッド）

## 最終下書き
（4媒体の本文をそのまま）

## 反応（投稿後3日経過時点で記入）
- YouTrust: いいね 32 / コメント 5 / DM 2
- LinkedIn: いいね 87 / コメント 12 / リーチ 4,200
- Facebook: いいね 41 / コメント 8 / リーチ 1,500
- X: いいね 124 / RT 18 / インプ 8,900

## 学び
（次回以降に活かせるTips。1〜3行）
```

### bad/ エントリの中身

```markdown
# {テーマ}

> 投稿日: 2026-XX-XX
> 担当: XX
> 失敗理由: （リーチ低い / 炎上気味 / フックが弱い 等）

## 何が悪かったか
（明確に言語化）

## どう直すべきだったか
（次回への教訓）
```

---

## 運用ルール

- **投稿後 3〜7日でreaction欄を埋める**（伸びた/伸びなかったの判断）
- **月1で全体を見返す**: パターンが見える
- **bad/ も恥ずかしがらず残す**: 失敗例の方が学びが大きい
- **PR / コミット時に追加**: GitHubに上げる時に lessons learned のメモも添える
